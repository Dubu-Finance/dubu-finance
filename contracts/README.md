# DuBu — proprietary AMM and aggregation router for GIWA

A prop AMM whose pricing is pushed on chain by an off-chain quoter, plus a router that aggregates
it against other venues. Targets GIWA (OP Stack L2, chain id 91342 on testnet, 1s blocks with
~200ms flashblock preconfirmation).

Full architecture and the reasoning behind each decision: [`../context/archi_v2.md`](../context/archi_v2.md).

## Layout

```
src/
  libraries/PropCurve.sol     the curve. pure, no storage, mirrored bit-for-bit in Rust
  interfaces/IPropPool.sol    the aggregator integration surface
  PropPool.sol                inventory, roles, quote push, settlement
  Router.sol                  adapter-based executor; no path finding on chain
  adapters/                   one per venue family
  reference/univ2/            faithful Uniswap V2 port — the comparison venue
  mocks/                      mintable tokens; GIWA has no real stablecoins yet
test/                         244 tests
testdata/curve_vectors.json   250 differential vectors, generated by the Rust engine
../engine/                    off-chain quoter; crates/dubu-core mirrors PropCurve
```

## Why the curve looks like this

Four prices and a capacity per side. A trade consuming the base interval `[u, u+q]` is charged the
average price over it, which for a linear ladder is exactly its midpoint value. Not a constant
product. Everything expressive — spread, skew, concentration, volatility response — is folded into
those four numbers off chain, so the strategy can change without a redeploy.

Two properties are load bearing, and both were arrived at by fixing a measured defect:

**Both sides are denominated in base.** Denominating the ask in quote makes its output
`amountIn * scale / avgAsk`, the reciprocal of the midpoint. `1/p` is convex, so by Jensen the
midpoint rule under-delivers and splitting an ask becomes strictly dominant for the taker —
measured at 0.004 bps excess on a 25 bps ladder, rising to 20.7 bps at 2000 bps.

**One rounding per trade, never on the price.** Quantising the impact term to a whole price unit
and then multiplying by trade size breaks monotonicity: an 18/6 pair at price 3e9 returned *less*
quote for one extra wei paid. Folding the price into the amount makes monotonicity provable across
the whole domain, which is also the precondition `getAmountIn` depends on.

## Running it

```
make build          forge build
make test           forge test
make ci             50k fuzz runs, 2048x128 invariants, plus cargo test and clippy
make vectors        regenerate testdata/curve_vectors.json from the Rust engine
make balance        deployer balance on GIWA Sepolia
make gas            current gas price and block height, both RPCs
```

`make ci` is the gate; the default profile is for iteration.

## What is deliberately not here

Reference-oracle deviation bounds, OnchainVerify spread tiering, and the RFQ path (a fork of
`okxlabs/Web3-DEX-EVM-PMM`'s `PmmProtocol`, which already carries the staleness decay this design
wants) are all later phases. No governance token — GIWA itself has none, for the regulatory reason
that a Korean exchange cannot handle a self-issued asset.

## Known gap

Ask exact-in costs ~149k gas against a 110k target, driven by the `log2(size/price)` bisection in
the quote-in inversion. The assertion in `test_Gas_Swap_ExactIn_AskSide_MissesTheTarget` is
two-sided, so closing the gap fails the test and forces this note and the architecture doc to be
updated rather than leaving a stale target behind.
